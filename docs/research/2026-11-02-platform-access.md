# 多平台商品评论采集：平台访问与风险调研

调研日期：2026-11-02  
适用范围：淘宝/天猫、京东、拼多多、亚马逊

## 结论

“任意商品 ID + 任意平台 + 自动取得全部评论”不是一个只靠爬虫技术就能兑现的产品承诺。四个平台的数据开放程度不同，部分页面还明确限制自动化访问。首版应按能力分级：

1. 有可用授权接口时，优先走授权接口。
2. 没有接口或接口权限不足时，只读取用户已经登录并可正常查看的页面。
3. 遇到登录、验证码、滑块或风险提示时暂停，由用户处理，然后从任务中断处继续。
4. 不把代理轮换、隐身指纹或验证码破解作为卖点，也不承诺绕过平台限制。

这个边界会降低“一键抓全站”的想象空间，但它能让失败原因、数据来源和用户责任保持清楚。对于个人竞品分析，这比一个偶尔能跑、随时封号和静默丢数据的脚本更实用。

## 平台能力矩阵

| 平台 | 商品标识 | 可用数据通道 | 首版建议 | 主要限制 |
| --- | --- | --- | --- | --- |
| 京东 | 数字商品 ID | 商家授权接口；页面可见评论 | 支持公开评论通道，失败时转浏览器协助；商家接口作为可配置扩展 | 接口有权限、字段和数据延迟差异；公开页面会变化或触发验证 |
| 淘宝/天猫 | `itemId` | TOP 商品评价查询；页面可见评论 | 有授权时调用接口；无授权时仅提供受控浏览器协助，按页面提示等待人工验证 | 平台条款限制未经许可的爬虫和自动化程序；接口权限按应用开放 |
| 拼多多 | 商品 ID | 商家侧接口；页面可见评论 | 不内置未授权抓取；支持授权导入或浏览器协助，实际能力由账号权限决定 | 用户协议限制机器人、蜘蛛等程序擅自获取平台内容；未找到可公开查询任意商品全部评论的开放接口 |
| 亚马逊 | ASIN | Creators API；页面可见评论 | 明确显示“无官方评论导出”；浏览器协助需遵守站点条款，采集失败时说明原因 | Creators API 的 `GetItems` 不提供评论资源；页面自动化受平台策略和地区规则约束 |

“支持平台”在本项目里指能够解析该平台的商品标识、创建统一任务、保存标准字段和解释错误。它不代表每个账号、地区和商品都一定能取得评论。

## 各平台事实

### 亚马逊

Amazon 的 PA-API 5 已停止使用。继续调用会得到 `403 Forbidden` 和 `AccessDeniedException`。目前应迁移到 Creators API。

Creators API 的初始账户额度示例为每秒 1 次事务、每天 8,640 次事务；请求超过额度时会返回 `ThrottleException`（HTTP 429），官方故障排查文档要求客户端使用指数退避，并遵循 `Retry-After`。

但 Creators API 的 `GetItems` 只列出 `BrowseNodeInfo`、`Images`、`ItemInfo`、`OffersV2` 等高阶资源，没有评论列表。也就是说，Creators API 适合商品元数据，不足以支撑“评论采集器”的核心功能。商品评论仍需依赖平台提供的其他授权数据、用户自有导出，或用户在页面中可正常看到的内容。

Amazon 计划政策还明确要求自动化访问如实回应人机判断，不得模拟人类速度或行为、完成或绕过验证码、规避平台访问限制。产品不能把“像真人一样操作”当技术方案。

来源：

- [PA-API 5 停用说明](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/paapiv5-deprecation)
- [Creators API 请求额度](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/concepts/api-rates)
- [Creators API 错误处理](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/troubleshooting/error-codes-and-messages)
- [Creators API GetItems](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/api-reference/operations/get-items)
- [Amazon 计划政策](https://affiliate-program.amazon.com/help/operating/policies)

### 淘宝/天猫

淘宝开放平台列出了 `taobao.pc.seo.review.query`（商品评价查询）。接口是否可调用，取决于应用、权限和授权会话，不能假设任意开发者都能查询任意商品。

淘宝网在调研时展示的协议要求第三方智能体或自动化程序在访问、调用或操作相关产品前取得事先、明确的书面许可并完成安全、合规评估。协议还规定，触发验证码或人机识别时应如实配合，不得绕过、破解或伪装。条款页标注的更新时间为 2026-10-07。

因此，淘宝适配器必须同时支持两种状态：有合法接口凭证时自动查询；没有凭证时只能提示需要授权，不能在后台偷偷启动未获许可的自动采集。

来源：

- [淘宝商品评价查询 API](https://developer.alibaba.com/docs/api.htm?apiId=70274)
- [淘宝网法律声明与相关协议](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_taobao/suit_bu1_taobao201811121436_80276.html)

### 京东

京东开放平台提供面向商家场景的评论查询能力。调研中确认的接口名称为 `jingdong.pop.PopCommentJsfService.getVenderCommentsForJos`，接口目录为京东宙斯开放平台。它服务商家侧查询，具有授权范围和非实时数据等限制，不能直接当作面向所有用户的公共评论 API。

原项目调用的 `club.jd.com` 评论接口不是面向开发者的稳定契约。它能工作，但字段、限流和错误形式都可能变化。首版可以保留这条低依赖路径，同时把 403、429、验证码页、空 JSON 和字段变化都显式报告给用户，不能静默生成空文件。

来源：

- [京东开放平台评论接口目录](https://jos.jd.com/apilist?apiGroupId=676)
- [原项目使用的评论页面](https://club.jd.com/)

### 拼多多

调研未找到可由普通开发者查询任意商品全部评论的公开开放接口。拼多多用户协议第 10 节相关条款将“通过机器人、蜘蛛等程序或设备擅自获取综合平台内的任何内容”列为禁止行为。

如果采集来自商家的授权接口，适配器应要求用户提供授权凭证和店铺范围。没有凭证时，产品可以打开用户本机的页面供其查看，但不能宣称获得平台许可，也不应自动处理验证。

来源：

- [拼多多用户服务协议](https://www.yangkeduo.com/pdd_user_services_agreement.pdf)

## 验证与反爬机制

### 常见机制

- **登录与会话校验**：未登录时只能看到部分评论，或评论请求直接返回权限错误。
- **JavaScript Challenge**：页面先执行脚本，再由前端携带计算结果发起后续请求。
- **动态 Token/签名**：请求头、Cookie、时间戳或请求参数绑定当前会话；复制一次请求未必能再次使用。
- **行为分析**：平台结合访问频率、路径、交互方式、设备与会话信号判断风险。
- **滑块、拼图和人机验证**：要求真人完成交互，或要求客户端如实声明自动化身份。
- **频率限制**：HTTP 429、业务错误码、临时空结果或延迟返回。
- **页面与接口结构变化**：DOM 类名、接口路径、字段名和分页方式会变。

阿里云 WAF 的公开文档展示了 JavaScript Challenge、动态 Token、行为分析以及人机验证类配置。这说明这些机制在行业内很常见，但公开文档不能证明某一电商页面当前使用了其中哪一项。项目文档避免把行业通用机制写成某个平台未经证实的具体实现。

来源：

- [阿里云 WAF 场景化防爬规则](https://www.alibabacloud.com/help/en/waf/web-application-firewall-2-0/user-guide/configure-anti-crawler-rules-for-websites)

### 产品的处理方式

| 遇到的情况 | 自动处理 | 交给用户 | 不做什么 |
| --- | --- | --- | --- |
| 网络抖动、5xx | 有限次指数退避 | 连续失败后显示原因和重试按钮 | 无限重试 |
| 429 | 读取 `Retry-After`，没有时指数退避 | 显示冷却时间 | 换代理继续打 |
| 登录 | 保持当前任务、停止读取 | 在有头浏览器中自行登录 | 收集账号密码 |
| 验证码、滑块 | 状态改为“等待验证”，停止后台请求 | 用户在当前页面完成 | 自动识别、破解或外包打码 |
| 页面结构变化 | 保留任务和已有数据 | 显示选择器或适配器版本错误 | 把空结果当作成功 |
| 无授权或平台禁止 | 阻止自动任务 | 提示改用授权接口或导出文件 | 隐藏风险继续运行 |

Playwright 支持持久化浏览器状态和监听页面网络响应，适合构建“用户在页面上完成登录，程序读取页面已经加载的结果”的本地工具。会话状态可能含有身份 Cookie，必须只保存在本机忽略目录，不能进 Git、日志或导出包。

来源：

- [Playwright Python 认证状态](https://playwright.dev/python/docs/auth)
- [Playwright Python 网络响应](https://playwright.dev/python/docs/network)

## 数据与任务设计上的直接影响

1. **评论 ID 不能保证都有**：不同平台可能只提供作者昵称、时间、内容和评分的组合。数据库需要先按平台评论 ID 去重，再用规范化字段哈希兜底。
2. **分页不能只靠页码**：页面滚动采集要记录已见评论指纹；终态由“没有新数据 + 页面没有下一页 + 未达到上限”共同判断。
3. **空结果不是成功**：必须区分“商品确实没有评论”“没有权限”“遇到验证”“接口结构变了”。
4. **保存中间结果**：每条评论入库后再更新进度，任务失败时已经采到的部分仍可导出。
5. **时间含义不同**：保留原平台时间文本，同时保存可解析时间；无法可靠解析时不要伪造时区。
6. **敏感信息最小化**：不保存账号密码、完整 Cookie、验证码截图和请求头中的令牌。

## 不建议采用的方案

- 用代理池和指纹伪装突破平台拦截。这会把维护成本和账号风险转移给用户，也直接违背多个平台的规则。
- 用云端集中保存多个用户的登录 Cookie。产品变成高价值攻击目标，个人分析场景不需要承担这种风险。
- 通过 OCR 或打码平台自动完成验证码。它绕过人机验证，不能作为合规采集能力。
- 只依赖固定 CSS 选择器。平台改版后整条采集链路会一起失效，且静默空结果很难发现。

## 对首版的范围建议

首版交付一个本机单用户工作台，包含统一任务、评论标准化、去重、增量续采、CSV/JSON 导出、演示数据和浏览器协助流程。平台通道按能力工作，不以“所有平台都能无人值守抓全量”为验收标准。

官方商家接口需要具体账号权限和合同，放进可扩展适配器边界；没有凭证时，界面必须告诉用户缺什么。这样既能承接京东原有脚本的用途，也不会用一套脆弱的网页选择器假装覆盖了四个平台的全部场景。
